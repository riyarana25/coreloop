# Theme fit

The theme name (a circular parts marketplace) comes from the participant. I could not find a published rubric or theme text in the sources I used (the hackathon aggregator page lists stages and prizes only). Treat this analysis as provisional until the organisers answer.

| Circular-parts element | Does CoreLoop touch it? |
|---|---|
| Used parts (cores) re-enter a remanufacturing loop | **Yes.** CoreLoop protects the return leg: cores must reach the OEM before the window closes or the loop breaks and the deposit is forfeited |
| Value recovery | **Yes**, measured in simulation (expired windows and unrecovered credit shortfall) |
| Marketplace (matching supply and demand between parties) | **No.** CoreLoop is single-dealer and single-direction. It is not a marketplace and is not presented as one |

Fit: **strong on circularity, weak on "marketplace" if read literally.**

Options considered:
1. Present CoreLoop as "the reverse-logistics reliability layer a circular parts marketplace needs" (a marketplace cannot clear cores that never ship or are never credited). This is an argument, not a feature.
2. Add the smallest real marketplace feature: a **surplus-core board** where a dealer that holds cores it cannot ship in time can flag them for another dealer in the same group that has a shipment to that OEM going out anyway. This is feasible with the existing consolidation planner. It is **not built** and would be labelled as simulated if added.
3. Ask the organisers whether a non-marketplace circular-flow product is in scope.

Decision: build and present option 1 now; keep option 2 as a documented extension; send question 3 if the participant chooses to. No marketplace claims in the deck.
